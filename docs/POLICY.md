# Условия Spotify и риски

Проект использует только официальные документированные возможности: Web API с OAuth 2.0 PKCE и управление воспроизведением
через Spotify Connect. Нет приватных эндпоинтов, нет обхода Premium или авторизации, нет парсинга интерфейса Spotify.
Расширение рисует **свой** интерфейс в Shadow DOM поверх страницы и не читает и не меняет элементы Spotify.

## Ограничения режима разработки (проверено по документации на ноябрь 2026)

- Нужен Premium у владельца приложения; не больше 5 пользователей в allowlist.
- Нет `/recommendations`, audio-features/analysis, related-artists, top-tracks артиста, browse, batch GET-запросов, popularity и followers.
- Поиск: `limit` ≤ 10. Очередь Spotify нельзя очистить или переставить через API.
- Квота считается на аккаунт разработчика; при `429 QUOTA_EXCEEDED` расширение продолжает из уже собранного пула.
- Web Playback SDK в MV3 недоступен (запрещены удалённые скрипты), поэтому звук играет Spotify Web Player, а расширение им управляет.

## Пункты Developer Policy, требующие внимания

| Пункт | Риск | Что сделано |
|---|---|---|
| Название | Имя приложения не должно начинаться с «Spot…» | Расширение называется «Songwave — Моя волна» |
| Не заменять основной опыт Spotify | Расширение — надстройка, звук и каталог остаются у Spotify | Нет собственного плеера, нет микса и кроссфейда |
| Не обучать ML на контенте Spotify | Ранжирование учится на **действиях пользователя** (лайки, пропуски), а не на аудио и метаданных каталога как обучающей выборке | Модель — линейная, 20 весов, хранится локально |
| Атрибуция | Показывать обложку и метаданные при воспроизведении | Обложка, название, артист, ссылка «Открыть в Spotify» |
| Публичный запуск | Для > 5 пользователей нужна заявка на расширенный доступ | Пока личный формат |
